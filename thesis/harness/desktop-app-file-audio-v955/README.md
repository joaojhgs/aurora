# C06 desktop app-owned file-audio source candidate

This is an unintegrated, private source candidate. It does not change the application checkout or create a production UI/API. The proposed hook is installed only in a Vite development build when the explicit desktop file-audio E2E flag is enabled, and it receives the currently mounted `AuroraTauriApp` runtime itself. It refuses any runtime other than `desktop-local` and any transport other than `tauri-local`.

The action uses one fixed WAV already used by the qualified audio flow (219,794 bytes, SHA-256 `da0ecc4ad0885746ab6e716585473917ab2b543a505bf0db09ebacfaa7943cbb`). It sends those bytes to `client.assistant.transcribeVoiceAudio` with the `accurate` route label, uses only the returned transcript as the text to `client.assistant.sendMessage` (`Orchestrator.ExternalUserInput`), and synthesizes only the returned assistant text via `client.assistant.synthesizeReadAloud` (`TTS.Synthesize`). Exact transcript and Paris predicates are enforced before proceeding to the next stage. Before the explicit synthesis request, the action also requires actual ExternalUserInput metadata to report `tts_status=skipped`; Root must separately admit the runtime configuration with automatic TTS readback disabled. This prevents double-counting an implicit Orchestrator readback plus explicit SDK synthesis. The report contains digests, IDs, timing, and the private TTS audio payload for custody; it never substitutes a transcript or reply.

The file request is the original mono 22,050 Hz WAV. This finite SDK action does not pass through the Rust native voice adapter's raw mono 16 kHz PCM conversion, so its result must not be described as that native preprocessing path. It also does not exercise CPAL capture or physical output playback. Exact resolved STT weights, Qwen configuration, Piper provider identity, and installed Tauri build remain Root admission/measurement evidence; the `accurate` request label alone proves none of those.

`tauri-app.patch` is a minimal integration sketch for `tauri-app.tsx` and `vite-env.d.ts`; apply only in a future approved candidate/build after the frozen desktop baseline is released. A future desktop runner should read the pinned WAV and call `window.__AURORA_DESKTOP_FILE_AUDIO_E2E__` with `{schema: "aurora.desktop_file_audio_e2e.payload.v1", runId, audioBase64}`, then retain the returned report and `synthesis.audioBase64` privately. The hook itself verifies exact byte count/hash and will fail closed on a different file. The current slice did not run a test, build, import, or desktop action; the patch has not been applied or typechecked.
