## Exact normal action and controlled input boundary

The ordinary focused action is Assistant push-to-talk, then Stop listening: use-assistant-voice.ts selects native ownership from the centralized surface profile; use-assistant-native-capture.ts:55–145 delegates start/finish through NativeDesktopVoicePort. The public start request contains only trigger and remoteAudioConsent (native-desktop-voice.ts:55–61), and its status intentionally excludes transcript/audio. Native DesktopAudioInput::runtime (native_voice.rs:1945–1951) selects CPAL production capture; the existing desktop-native-voice-e2e debug gate substitutes a generated square wave, not the frozen WAV. There is no file/PCM argument on this inspected native start path. Chromium --use-file-for-fake-audio-capture is not established ingress for CPAL/WebKit/Tauri and must not be borrowed from the separate browser condition.

Thus the exact missing action is an actually supported, owned desktop controlled-WAV ingress into this native capture path, or an explicitly scoped finite-audio SDK action exercised through the actual desktop surface. Host audio routing/installed input devices have not been inspected or admitted here. This report does not design a new flag, seed profile/storage, inject transcripts/replies, authorize a new condition, or claim a file-upload product control exists. Once a valid ingress is admitted, ordinary PTT start/finish remains the native user action; finite SDK audio uses actual WAV bytes → returned transcript → actual Assistant text → Synthesize, never fixed transcript/reply substitution.

## Same frozen setup: selectable, not established

Gateway ports permit the same Python BASE faster-whisper / Qwen3.5-0.8B Q4_0 / Piper ljspeech setup when the selected real sidecar/server actually loads those exact files/options. Native Gateway STT must select the existing accurate route explicitly: native_voice.rs:2666–2672 defaults to realtime when no gateway_stt_model_id is provided; apply_speech_stages:3577 can bind the admitted model route. Transcription service.py:726–765 resolves accurate model_size_or_path/device/compute_type. The route word accurate is not itself proof of BASE weights. Chatbot.py:459–498 uses configured llama.cpp model path/options (with environment override precedence); neither surface label nor model display name establishes frozen weights/backend/offload. Config schema retains actual llama.cpp options, including seed/threads. Exact runtime constructor/options/asset hashes remain necessary admission.

Native Gateway TTS chooses the server's configured voice (native_voice.rs:2758–2762) and its stage-selection path rejects explicit Gateway TTS model selection (:3590–3596). The server must already have the admitted Piper default; a native local Piper-labelled pack is not proof of the same Python Piper CLI. Native adapters use finite raw mono PCM at their configured 16 kHz STT binding and request a 16 kHz WAV for native TTS (gateway_stt.rs:269–285; gateway_tts.rs:268–282). This conversion/request parameter must remain explicit; do not claim byte-identical native request/output to a 22.05 kHz file-input baseline. Same weights are possible without implying identical audio preprocessing or compute backend.

NativeGatewayTts validates decoded nonempty PCM16 mono WAV shape/sample rate (gateway_tts.rs:289–310) before native output. This supports structural audio validity; it does not itself reject an all-zero waveform or establish actual acoustics/first-audio evidence. Actual non-silent output remains a result check. Normal Read aloud also differs by surface: use-assistant-tts.ts:175 uses TTS.Request for a sidecar, whereas :194 uses TTS.Synthesize plus client audio for a non-sidecar. A successful label or browser speechSynthesis fallback cannot certify frozen Piper audio. Existing native/SDK result and actual output custody must identify which path really ran.

Runtime role remains independent from physical desktop surface: platform-surface.ts:172–216 resolves usesLocalSidecar, nodeMode, runtimeTier and ownsLocalNodeState separately; aurora-client.ts:1045 vs :1150 selects thin runtime vs Tauri local transport. No compiled role/environment override is required or approved. The default desktop-local-minimal bundle intentionally excludes STT/TTS/local ML dependencies (TAURI_DESKTOP_BUILD.md sidecar profile table); local audio/accelerator package or actual admitted equivalent is required, with model assets external. No installed app, artifact, OS audio/device, keyring/reopen, rendered reply/history, exact model runtime, native event/stage timing, or full C06 acceptance was verified here.
