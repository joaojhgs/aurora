## Source-supported boundaries and limits

- **File audio:** the retained desktop harnesses supply a fixed PCM WAV through browser file-backed microphone or the Python request path. Android’s native debug PCM command is compiled only for Android debug builds with `android-voice-live-test` (`apps/aurora-tauri/src-tauri/src/lib.rs` around the `android_voice_live_test` registration); it is not a general production file-import route. Normal Android native capture is microphone-owned. Packaged Android PTT follows the native-ready, native-unready and no-native-port capture branches above; only the last uses focused WebView capture. None establishes a packaged production file-audio input capability.
- **Local vs remote:** local browser speech, native Android speech, local Python services, HTTP API and mesh are distinct route cells. For API/mesh, a configured stage map is not actual-provider proof; retain actual stage/provider, request correlation and route evidence. The source does not authorize falling back to another engine or smaller/different model while counting the pinned condition.
- **Model selection:** native mobile has an exact Qwen GGUF catalogue descriptor and validates its file SHA. Browser catalogues instead expose downloadable Sherpa speech assets. Python configuration supports local Faster-Whisper paths and Piper CLI model/config paths. Matching a display/model ID is insufficient to claim byte-level or backend equivalence.
- **Runtime unknowns:** no fresh device, browser, build, service, model import, network or benchmark was run. No current C07 mobile or C08 Android installation/readiness is inferred from source. Exact installed asset presence, permissions, selected runtime role, local model load, physical host/device identity, actual stage routing, answer, history and per-device resources remain for Root’s separately admitted main-flow evidence.
