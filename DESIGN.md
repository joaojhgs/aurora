# Aurora Production UI Design Contract

Status: current design source for the Tauri/web/mobile cockpit production pass.
Evidence reviewed: `modules/ui-mock-reference/components/aurora/app-shell.tsx`, `modules/ui-mock-reference/lib/aurora/nav.ts`, `packages/aurora-ui/src/nav.tsx`, `packages/aurora-ui/src/production-surface-contracts.ts`, `apps/aurora-tauri/src/tauri-app.tsx`, `docs/TAURI_DEV_AND_UI_GAP_REPORT.md`, and `docs/PRODUCTION_UI_CONTRACTS.md`.

## Product personas

- **Local desktop assistant user** — runs Aurora in Tauri local mode, expects chat-first assistant UX, visible local/remote/mesh route choice, truthful native capability state, and safe shutdown/diagnostics.
- **Remote web operator** — connects to an existing Gateway, can observe services and policies without native claims, and sees disabled desktop-only controls with repair guidance.
- **Mesh admin** — manages peer trust, pairing, route quality, RBAC, tokens, and audit trails through explicit AdminAction confirmations.
- **Mobile thin client user** — uses Android/iOS as a thin shell with honest permission, assistant-role, background, secure-storage, and pairing limits.

## Information architecture

- **Assistant**: `/`, `/memory`, `/tools`, `/mesh` for chat, knowledge, tool approvals, and peer context.
- **Operate**: `/admin`, `/admin/services`, `/admin/access`, `/admin/tokens`, `/admin/devices`, `/admin/config`, `/admin/contracts`, `/admin/plugins`, `/admin/pairing`, `/admin/backups`, `/admin/scheduler`, `/admin/audit` for operator controls and auditability.
- **Runtime**: `/models`, `/diagnostics`, `/onboarding`, `/settings`, `/memory/policy`, `/settings/native` for model/runtime posture, support evidence, setup, privacy, and native platform truth.

## Shell contract

The shell follows the mock cockpit structure: grouped desktop sidebar, mobile sheet menu, bottom tabs for primary mobile surfaces, route status chips, local/thin mode evidence, and route-specific page landmarks. Diagnostics are a dedicated route, not a substitute for missing product pages. Every primary route must resolve through a typed registry and render a route-specific component.

## Regression gates

- The Tauri registry must contain every `packages/aurora-ui/src/nav.tsx` primary nav item ID.
- No primary route may render the legacy `TauriRoutePlaceholder` copy: `This Tauri route is now navigable` or `A full product page still needs to be mounted`.
- Each route must expose at least one route-specific landmark/control from the inventory above.
- Route policy gates must distinguish selector, consent, privacy indicator, native permission, and AdminAction states.
- Tests and docs must not claim desktop-local/mobile support unless native/Tauri evidence is collected or an explicit unsupported/degraded state is rendered.
